# Multi-Module Expansion — Design

**Date:** 2026-08-12
**Builds on:** [2026-08-11 letter-matching design](2026-08-11-kids-letter-matching-app-design.md)
**Scope:** 8 learning modules, ~400 levels, Go backend, free/paid gating, iOS parity.

## What changes

v1 shipped one game type with 15 hand-written levels. This adds seven more
modules, generates levels from data instead of hand-authoring them, adds a shell
(header/footer) around the game area, gates levels behind a free/paid line, and
builds the backend the content contract was always shaped for.

## Illustrations are emoji

Every picture in this app — animals, objects, shapes, food, the avatar — is an
emoji codepoint, not an image file.

This is not a shortcut, it is the right call: zero image assets, zero licensing,
zero download weight, crisp at any size, and full offline operation. A child
cannot tell 🐘 from a drawn elephant, and the system emoji font already ships
every picture this curriculum needs.

The one cost: emoji render through platform fallback fonts, so they look
slightly different on iOS and Android. Acceptable.

## Content contract v2

v1's contract had one flat list of games. Eight modules with different shapes
need a level's payload to be module-specific, so the core stays small and a new
module can be added without touching shared models.

```json
{
  "bundle_version": 2,
  "modules": [
    {
      "id": "alphabet",
      "title": "Alphabet",
      "icon": "🔤",
      "free_levels": 5,
      "levels": [
        {
          "id": "alphabet_01",
          "level": 1,
          "prompt": "Tap a letter to hear it",
          "data": { "letters": ["A", "B", "C"], "words": {"A": ["apple", "🍎"]} }
        }
      ]
    }
  ]
}
```

- **`data` is opaque to the core.** Each module owns its own parser. The core
  routes on `module.id` and hands `data` over untouched.
- **`free_levels: N`** means levels 1..N are playable free; the rest need
  entitlement. One integer, per module, set by content rather than code.
- Everything else carries over from v1: relative asset paths, no envelope,
  unknown modules skipped so old apps survive new bundles.

## Modules

| # | Module | Interaction | Levels |
|---|---|---|---|
| 1 | Alphabet Discovery | Tap a letter → hear name, phonic, word; emoji animates | 52 |
| 2 | Find the Letter | Audio prompt → tap matching letter among 3-6 | 60 |
| 3 | Match Upper & Lower | Drag uppercase onto its lowercase partner | 52 |
| 4 | Phonics Listen & Choose | Hear a sound → pick the letter that makes it | 52 |
| 5 | Letter Tracing | Trace the letterform with a finger; path fills | 52 |
| 6 | Word Builder (CVC) | Drag letters into slots to spell the pictured word | 50 |
| 7 | Numbers & Counting | Count emoji, tap the numeral; and the reverse | 60 |
| 8 | Shapes & Colours | Sort objects into colour/shape-coded baskets | 50 |
| 9 | Voice Quest | Say what the picture is; speech recognition | 50 |

Nine modules, 478 levels. All generated by `tools/gen_content.py` from letter,
word, number and colour tables — hand-authoring 478 levels is not maintainable
and would drift from the validation rules.

## Voice Quest, honestly

Speech recognition is trained on adult speech and performs badly on
three-to-five year olds. A child who says "elephant" correctly and is told they
are wrong is exactly the fail state the whole app is designed to avoid.

Rules for this module:

- **The attempt is the reward.** Speaking at all advances the level. Recognition
  quality affects the celebration, never the progression.
- **Matching is forgiving** — case-insensitive, whitespace-stripped, accepts any
  alternative in a per-level list, and accepts a close match by edit distance.
- **No "wrong".** An unrecognised answer plays the correct word and moves on
  warmly. There is no failure branch to write.
- **Degrades to a tap.** If the microphone is unavailable or permission is
  refused, the level shows a "tap when you've said it" button and still works.

## Shell

A persistent frame around every module:

- **Header** — back button (leftmost, large), module title, star count.
- **Footer** — level dots showing position in the module, a lock icon past the
  free line.
- Both sized for a small hand: nothing below 56pt, back button 64pt.

The game area keeps the v1 rules: no timer, no score, no lives, no fail state.
Stars are earned, never lost.

## Free vs paid

The data model and gating ship now; store integration does not (it needs real
developer accounts and product IDs).

- `free_levels` per module in the bundle.
- `Entitlements` — a locally stored flag, `isPremium`, default false.
- Locked levels render with a lock and, on tap, show an upsell sheet.
- `Entitlements.isPremium` is the single gate. Wiring it to a real purchase
  later means setting that flag from a receipt check — nothing else changes.

**A locked level is never a dead end.** The child is returned to a playable
level, and the upsell is addressed to a parent, not the child.

## Daily challenge and stars

- Stars: one per completed level, persisted, shown in the header.
- Daily challenge: 3-5 levels picked across modules from what the child has
  played, refreshed each day.
- A local notification (not push) at a parent-set time. Local means no server,
  no tokens, no network, and it complies with kids-category rules by default.

## Backend (Go)

```
cmd/api/main.go        entry, routing, graceful shutdown
internal/bundle/       content store + validation
internal/progress/     progress + entitlements
internal/httpapi/      handlers
migrations/            schema
```

Endpoints:

- `GET /v1/bundle?since=<version>` → bundle JSON, or `304`
- `POST /v1/progress` → completed level ids + stars
- `GET /v1/progress/:device` → the same, for a new install
- `GET /v1/entitlements/:device` → `{"premium": bool}`
- `GET /healthz`

Postgres with the bundle stored as JSONB. `net/http` with Go 1.22 method
routing — no framework needed for five endpoints. The same validation rules the
app's `bundle_test.dart` enforces run server-side on upload: every level
winnable, no unwinnable or trivially-free level, ids unique.

## Testing

- Unit tests per module state machine (pure Dart, no widgets).
- Widget tests per module screen.
- Content validation over the generated bundle — the rule that matters is that
  no level can be unwinnable.
- Go: handler tests against an in-memory store, store tests against Postgres
  when `DATABASE_URL` is set.
- An end-to-end widget test that launches the app, enters a module, completes a
  level, and confirms a star was earned and persisted.

## Not in scope

- Real IAP purchase flow (needs developer accounts).
- Story Time (2.9) — needs authored narrative content, not generatable.
- Daily Routine Tracker avatar animation — the notification and star mechanics
  ship; the dressed avatar does not.
- iOS build verification — code and config are complete, but only a Mac can
  confirm it.
